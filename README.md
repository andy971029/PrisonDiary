# 服刑日誌（網頁版）

楓之谷：經典版的經驗值計算器，整個在瀏覽器裡跑。用瀏覽器的「分享視窗」看遊戲畫面，
讀狀態列的經驗值，算出 EXP/hr 與升級剩餘時間。不用安裝程式，也完全不接觸遊戲程序：
不注入、不讀記憶體、不攔封包，只看分享出來的畫面。

這個 Repo 從 [MapleExpTool](https://github.com/andy971029/MapleExpTool) 拆出來，只留網頁版。
辨識與追蹤邏輯和桌面版是同一套 Python 程式碼，用 [Pyodide](https://pyodide.org/) 在瀏覽器裡執行。

## 使用

直接用 Chrome 或 Edge 開 https://andy971029.github.io/PrisonDiary/ ，什麼都不用裝。
每次 push 到 main，GitHub Actions 會先跑測試，通過才重新打包並發布。

### 在自己電腦跑

需要 Python 3.11 以上（只用來打包與開本機伺服器）和 Chrome 或 Edge。

```powershell
git clone https://github.com/andy971029/PrisonDiary.git
cd PrisonDiary
.\web\serve.cmd
```

1. 用 Chrome 或 Edge 開 http://localhost:8765/ 。
2. 等按鈕從「載入 Python 環境…」變成「分享遊戲視窗」。第一次要下載約 10 MB 的 Pyodide 與 numpy，之後瀏覽器會快取。
3. 按「分享遊戲視窗」，在對話框選「視窗」分頁、挑遊戲視窗。
4. 想邊玩邊看，就按「開啟小浮窗」。

## 功能

- **經驗值與速率：** 用字元模板比對讀經驗值，不用 OCR。實測 OCR 讀數字幾乎全錯。
- **遊戲放大顯示：** 視窗開得比遊戲的解析度大時，遊戲不是多畫一點，而是把整張畫面放大、補黑邊（實測 2560x1599 的視窗是 1366x768 放大 1.874 倍），狀態列的字跟著變大，內建字形就比不到。經驗值欄位找不到時，每 5 秒猜一次原本的解析度（1366x768、1920x1080、1280x720、1600x900、1024x768）：從非黑色的範圍量出遊戲畫面，用最近鄰取樣縮回去，找得到經驗值欄位的就是它（`src/mapleexp/vision/scaling.py`）。之後網頁每格都照那個框縮好才送進辨識（`drawImage` 關掉平滑，取樣點與 `scaling.resample` 相同），經驗、楓幣、祈禱、小地圖都照原尺寸讀；分享的畫面大小一變就重新判斷。放大後小數點落在最下面兩列，內建字形另有一組這樣的 `.0`～`.9`。
- **字形回報：** 楓幣與等級的數字內建字形對不上時，用 OCR 讀出來再把那組字形學起來；學會的每一個字形（形狀、讀到的整個數字、畫面大小、網頁版本）會排進瀏覽器的待送清單（localStorage 的 `mapleexp.glyphs.v1`，最多留最新 500 個）、送到後端的 `POST /api/glyphs`：開頁、學到新的、恢復連線時送，失敗五分鐘後再試，送成功才從清單拿掉。跟排行榜的紀錄一樣一律上傳（v0.44.0 起沒有開關）。目的是收集各台電腦實際學到的長相，整理後放進內建字形，讓大家照同一套讀；學字形本身留著當沒見過的情況的備案。v0.43.0 以前學到的字形只在記憶體裡，沒有回報。
- **楓幣收益：** 背包視窗開著時讀背包底部的楓幣欄位，算楓幣/hr、最近 10 分鐘與整場的累計。背包可以放在畫面任何位置，程式會自己找（認「楓幣框＋楓葉點數框」上下成對的白框）；拖走或關掉後會重新找。背包關著的時間不計入，短暫被滑鼠擋住則照算。數字用模板比對，沒看過的字形先交給 OCR 讀、讀對了再學起來。
- **角色、職業、等級、地圖：** 用 Tesseract.js 辨識。中文走 `chi_tra`，等級的數字走英文模型。語言檔第一次要下載幾十 MB，之後存在瀏覽器的 IndexedDB。
- **歷史紀錄：** 以「角色 × 地圖」為一段，結算時確認才存進瀏覽器的 localStorage。活躍不滿 10 分鐘的段不記錄：結算時直接丟掉（結算視窗會說有幾段），以前存下來的短紀錄開頁時也會移除。只存在這個瀏覽器，可以匯出 JSON。
- **診斷快照與問題回報：** 辨識讀錯時光看紀錄查不出原因，所以網頁會把辨識當下拿到的畫面也傳給後端（一律上傳，跟紀錄一樣沒有開關）。自動的只傳診斷面板那幾塊原尺寸的裁切圖（經驗值、等級、職業、角色名、地圖名稱、楓幣、祈禱；找不到小地圖時另外裁畫面左上角 360×260）與當時的引擎狀態，沒有整張畫面，一份通常不到 20 KB：每一段紀錄在開始那一格與最後一次（每分鐘更新）各拍一組，存檔時跟著紀錄的 `uid` 傳上去（段是照「角色 × 職業 × 等級 × 地圖」分的，讀錯就會多一段，它開始那一格正好是讀錯的那一刻；讀不到角色名字的段也傳，只是沒有 `uid`）；辨識一直讀不到某樣東西（經驗值欄位、地圖名稱、角色名字、職業、等級）超過 15 秒時再拍一份，每次分享每種只拍一次。待送的放在 localStorage 的 `mapleexp.snapshots.v1`（最多 30 份），送不出去五分鐘後再試。頂列的「回報問題」鈕是給使用者主動回報的：按下去會把當下的整張畫面凍結起來給使用者看，加上描述、同一組裁切圖、引擎狀態、最近 150 格的辨識結果與 log 一起送出，回一個六個字的回報代碼（自動複製），使用者跟作者聯絡時附上代碼就好，不用自己截圖。沒在分享時也能回報，只是沒有畫面。
- **修正角色名字：** 角色名是 Tesseract 讀的，它認不得一些少見的字（實例：「o婗婗o」的「婗」三個倍率讀成 媚、如、盡），也會多讀一個標點（「,卍米糕玄師寢」）。名字那一行先拿掉標點與空白，三個倍率投票：兩個以上讀得一樣就用它，都不一樣時字數相同的逐字投票，再不行才取最長的。投票救不了的字由使用者自己改：上方「角色」旁的鉛筆鈕打開「修正角色名字」，填上正確的名字，勾選要一起改名的舊名字（畫面上讀到的與相近的名字預設勾好）。正在分享時，網頁記下名牌上名字那一行的墨跡（文字覆蓋率過半的像素，裁到剛好包住字）與正確的名字，存在 localStorage 的 `mapleexp.namefix.v1`（最多 20 筆）；之後名牌的墨跡跟它比，大小差不到一個像素、錯開一個像素內不一樣的像素不到墨跡的 12% 就算同一塊，直接用修正的名字、不管 OCR 讀成什麼（同一塊名牌在雜訊下差 3–10%，換掉一個字差 30% 以上）。勾選的舊名字：這個瀏覽器的歷史紀錄、還沒結算的這一次、還有這個瀏覽器傳上排行榜的紀錄（`POST /api/records/rename`，只改自己金鑰名下的）都改成新名字；排行榜那邊改不成就整個不動。
- **排行榜：** 上方的「排行榜」頁籤（網址 `#rank`），資料是大家上傳的練功紀錄，由後端（`server/app.py`）算好、網頁呼叫 API 抓來顯示。「個人排行榜」分總累計經驗、最高效率、等級三塊，每塊上面是前三名的頒獎台，下面是完整名單；頒獎台上站的是玩家自己設的紙娃娃造型，名單每一列前面是同一套造型的頭像，沒設的是空的剪影；這個瀏覽器傳過紀錄的角色（自己的角色）會用琥珀色的框標出來，點它的紙娃娃或頭像會切到紙娃娃頁籤、把「排行榜造型」鈕亮起來；「練功排行榜」（`#rank/train`）把同一張地圖、同一個職業、同一個 10 級區間的紀錄合起來算平均 EXP / hr，可以依職業與等級區間篩選，看哪裡好練；地圖名稱點了會彈地圖小卡（小地圖、NPC、通往哪裡、怪物），跟圖鑑裡的地圖小卡是同一張。兩個都能切全部、近 30 天、近 7 天；向後端抓資料的時候整張卡片會蓋一層「載入中」的遮罩。版面跟圖鑑一樣不出現外層捲軸：卡片撐滿視窗剩下的高度，名單與表格在卡片裡面捲。上傳是自動的：後端網址（`web/index.html` 的 `SYNC_API`）有設的時候，每次開啟網頁把手上的歷史紀錄整批傳一次，每次儲存紀錄再傳新的那幾筆；讀不到角色名字的不傳，只留在瀏覽器（活躍不滿 10 分鐘的段連歷史紀錄都不進）。傳上去的紀錄不一定算進排行榜：要有等級、職業與地圖名稱都在後端的合法清單裡，而且不是女神組隊任務的地圖（解任務拿的經驗不算練功）；不算的照樣收下，網頁的 log 會寫出哪一段為什麼不算，歷史紀錄的說明也會列出有幾段不算。上傳的是角色、職業、等級、地圖、起訖時間、經驗與秒數，後端另外記下上傳者的 IP（不對外顯示）；結算視窗會先講明。上傳一律開著（v0.44.0 拿掉了設定裡的開關）。排行榜造型在紙娃娃頁籤設：按「排行榜造型」，從這個瀏覽器傳過紀錄的角色裡挑一個，把目前的造型套上去（一個角色一套，也可以拿掉）。傳上去的是造型的零件編號（膚色、髮型、臉型、混色、各部位的時裝、武器類型），不是圖片，排行榜再用紙娃娃的資料把站姿畫出來。後端靠瀏覽器自己產生的一把金鑰認「這個角色的紀錄是不是這個瀏覽器傳的」：同一個角色在兩台電腦都有紀錄就兩邊都能改、後設的蓋掉先設的；清掉網站資料金鑰就換一把新的，要等下次再上傳那個角色的紀錄才能再設。沒有登入也沒有帳號，所以只是「傳上去」：不能換一台電腦把紀錄抓回來，傳上去的也不會因為在歷史紀錄裡刪掉或全部清除而從排行榜消失。後端只靠每筆紀錄的 `uid` 認重複：`uid` 是網頁從紀錄內容（紀錄編號、角色、起訖時間、經驗）算出來的指紋，同一筆不管重傳幾次都是同一個，後端已經有就不再存。後端連不上時紀錄先留著，五分鐘後、下次開頁或恢復連線時再傳。數字是瀏覽器算好傳上去的，後端只擋格式不對與明顯不可能的值。
- **經驗加倍試算：** 經驗收益右上角可以選「無加倍」「1.5 倍」「2 倍」（預設無加倍），速率、累計與倒數都照倍數顯示，不影響歷史紀錄。
- **神聖祈禱倒數：** 不用按任何按鈕，分享畫面後就會每格到畫面右上角第一排 buff 裡找神聖祈禱的圖示，視窗模式（buff 在遊戲視窗頂端、不在畫面頂端）找不到時，隔幾秒再到畫面上半部大範圍找一次（連續找不到就越隔越久，最長 30 秒），找到後就跟著位置走，圖示不見再出現時先看原來那一列，讀它左下角的剩餘時間。白色數字代表分鐘，顯示「1m+」；剩不到一分鐘會變成黃色的秒數。數字不靠文字辨識：0～9 的字形都內建（取自分享串流的實際畫面），0～59 每個數字該長什麼樣整塊拿去跟畫面比亮度、取最像的，分不出高下就這一格不讀，所以兩個數字黏在一起或畫面糊掉時，不會只讀到半個數字。每讀到一次秒數就算出一個「結束時刻」，最近五格裡有三格算出同一個時刻才採用，偶爾讀錯的那一格跟別格對不上、自然不算數；白色剛變黃色的那一刻剩 60 秒，所以第一格黃色就開始倒數。兩次截圖之間由網頁自己往下數。圖示快結束時會由下往上變灰，比對時每一列各自正規化，所以灰掉的部分照樣認得出來。寵物重放後自然接到下一輪，不用設定祈禱等級。剩下秒數到「警示倒數」時會用設定好的顏色閃爍與音效提醒；祈禱自然結束（寵物沒重放）也會提醒：歸零後圖示還會留幾秒、上面沒有數字、一閃一閃地消失，這時算「結束了」，不會被當成一分鐘以上。圖示暫時找不到（滑鼠移過去跳出說明、被視窗或特效擋住）時倒數照走、不會消失，一路被擋到時間到也照樣提醒。沒用祈禱時按鈕只顯示「—」。點一下祈禱鈕可以關掉提醒（虛線框、圖示變灰、多一個紅色靜音鈴鐺），倒數照樣顯示，再點一下打開。電腦比較吃力或沒在用祈禱時，可以在「設定」裡關掉「辨識神聖祈禱」，就完全不找圖示，按鈕和其他祈禱設定也會一起藏起來。
- **女神組隊任務小工具：** 主頁有一塊「女神組隊任務」，四關的圖和工具一次排開：休息室（每天要蒐集的唱片，依台北時間標出今天）、封印之室（照著按 NPC 說的 0／1，一步步排出台階人數，最多 5 次）、倉庫（地圖上標好紅獨角獅出現的順序）、中央塔（參考圖），地圖名稱讀到哪一關就把那關框起來。小浮窗角色那一行右邊的「女神」鈕，按下去把經驗、楓幣換成同樣的小工具（用分頁切關卡，進到關卡會自動選好那一關），再按「經驗」換回來；封印之室的進度兩邊共用。
- **功能頁籤：** 頂列左邊標題底下切換「練功助手」（上面這些）與「圖鑑」（怪物、道具、裝備、任務、NPC、地圖）；跟讀畫面有關的東西都在頂列右邊：控制鈕一列、底下是讀到的角色、職業、等級與地圖，在哪一頁都看得到，分享照跑。選了哪頁記在瀏覽器裡，網址加 `#book` 直接開圖鑑。
- **職業：** 圖鑑與紙娃娃中間的分頁（網址 `#job`，`#job/110` 直接開狂戰士），列出每個職業的轉職分支與技能。上面一排是系統（初心者、劍士、法師、弓箭手、盜賊、海盜、皇家騎士團、狂狼勇士），選一個就畫出它的分支圖：左邊是起點的職業，往右一轉一轉排，每條路一列；點圖上的職業，下面列它的技能。技能排成卡片，每張只有圖示、名稱、最高等級與說明；點卡片彈一張小卡，裡面是前置技能、四轉技能吃技能書之前的上限，以及每一級的效果。可以跨職業搜尋技能名稱。資料是客戶端技能資料的快照（`scripts/export_skillbook.py` 產生 `web/skillbook.json`，格式見 `src/mapleexp/skillbook.py`）：每一級的效果是客戶端的句型（例如「消耗MP#mpCon，攻擊力#damage%」）把代號換成那一級的數值，跟遊戲裡技能視窗那行字同一個來源；有幾個代號是客戶端另外算的，名字看得出算法的照著算（熟練度是 10＋5×mastery、攻擊範圍取範圍矩形的寬…），看不出來的不猜，那個位置印「？」（目前常用技能裡只有楓幣炸彈的熟練度）。客戶端標成不在技能視窗顯示的技能（還沒開放的四轉技能、騎寵、活動技能）預設不列，打開「含隱藏技能」才列。技能圖示打包成一張圖集 `web/icons/skills.png`（要 UnityPy 才匯得出來；沒有 UnityPy 的環境跑匯出腳本只更新文字，圖示沿用上一次的）。沒有職業名稱表，職業代碼對名字與分支寫在 `skillbook.py` 裡。分支圖右邊的「技能／攻略」切換到攻略（網址 `#job/110/guide`）：選到的職業從一轉一路印到它自己（選十字軍就是劍士 → 狂戰士 → 十字軍），內容有能力值、各轉的技能配點與思路、轉職地點、裝備重點與來源；四轉印「尚未開放」；初心者那頁是版本現況、轉職流程、練功地圖與必解任務。內容是手寫的 `web/jobguide.md`（2026-11-22 整理自巴哈經典版哈啦板與陸服資料站），「# @職業代號」分段，只認標題、條列、表格、粗體與連結，改攻略直接改這個檔。
- **圖鑑的「全部」：** 圖鑑分頁最前面的分類，把怪物、道具、裝備、任務、NPC、地圖排在同一張表裡，不用先想要找的東西是哪一類，打名字就找得到（沒選過分類的人從這裡開始，網址 `#book/all`）。搜尋只比名稱（地圖連地區一起比），名字完全一樣的排最前面、開頭一樣的其次；沒在搜尋時一類一類排。欄位是名稱（照各分類自己那一欄畫，圖示與「未開放」這些標記都一樣）、類別（後面的小字是細類：消耗、單手劍、任務的區域、NPC 的職稱…）、等級、一行重點（怪物的 HP 與 EXP、道具的效果、裝備的職業與攻防、任務在哪接與獎勵、NPC 在哪幾張圖、地圖有哪些怪），類別與等級可以排序。點一列展開的就是它在自己分類裡展開的那一塊。可以只看某一類；預設不列沒有圖鑑卡或還沒開放的怪、接不到的任務、不在場的 NPC，打開「含未開放、接不到的」才列；「以所在地圖篩選」在這裡一樣有效。
- **怪物圖鑑：** 從遊戲客戶端的資料檔匯出的快照（`scripts/export_monsterbook.py` 產生 `web/monsterbook.json` 與 `web/mobs/` 的怪物圖，客戶端改版重跑一次；匯出圖要另外 `pip install UnityPy`）。每隻怪的站姿圖（列表是縮圖，展開看大圖，太大的 Boss 縮到 256 像素）、等級、HP、MP、EXP、EXP/HP、物防、魔防、命中、迴避，加上圖鑑卡上列的掉落物與出現地圖（沒有機率，掉落率在伺服器端）。出現地圖不是抄圖鑑卡，是從客戶端的地圖資料（每張地圖的怪物生成清單）算的：客戶端只放已開放區域的地圖，所以沒出現在任何一張地圖的怪就是還沒開放的（武陵、童話王國那些），預設不列，要看打開「含未開放的怪」，展開時會列圖鑑卡上寫的、以後會出現的地方。搜尋同時比對怪物名、型態、掉落物名與地圖名，可以用等級範圍篩、只看「目前地圖的怪」（讀到地圖名稱後才能按），點一列展開圖鑑說明、掉落物與出現地圖；掉落物是帶圖示的小籤，裝備依職業、道具依類別分組，點一個彈出那件東西的小卡（數值、效果、說明、會掉的怪）。預設只列有圖鑑卡的野怪，任務、活動、召喚物要打開「含沒有圖鑑卡的怪」。
- **道具與裝備圖鑑：** 圖鑑分頁裡再分「怪物」「道具」「裝備」。道具與裝備也是客戶端資料的快照（`scripts/export_itembook.py` 產生 `web/itembook.json`，圖示打包成 `web/icons/` 的兩張圖集，要先跑過怪物圖鑑的匯出）。裝備列需求等級、職業、STR／DEX／INT／LUK 需求、攻擊、防禦、其他加成、可升級次數，可以用類別、職業、等級範圍篩；道具列類別、效果（藥水回復量、料理增益與持續時間、卷軸成功率與加成）、等級、商店價。兩邊都有「會掉的怪」：從怪物圖鑑卡反查、只算已開放的怪，展開後是帶怪物縮圖的小籤，點一個彈出那隻怪的小卡（數值、說明），可以只看怪物會掉的；另有「任務獎勵」：接得到的任務會給這個當獎勵的，點一個彈出那個任務的小卡，也可以只看任務給的。商店賣的、NPC 製作的客戶端裡沒有資料（製作配方在伺服器端）。現金裝與現金道具不列。
- **任務、NPC、地圖圖鑑：** 同樣是客戶端資料的快照（`scripts/export_worldbook.py` 一次產生 `web/questbook.json`、`web/npcbook.json`、`web/mapbook.json`、`web/npcs/` 的 NPC 站姿圖與 `web/minimaps/` 的小地圖，要先跑過怪物與道具圖鑑的匯出）。任務列區域、等級、職業、接任務的 NPC、EXP、楓幣、獎勵道具，展開看接／交任務的 NPC、前置與接續任務、要交的道具與要打的怪、獎勵（固定給、擇一、隨機，附職業與性別限制）與接任務前、進行中、完成後的說明；預設只列接得到的（接任務的 NPC 站在已開放的地圖上、活動沒結束）。NPC 列職稱、所在地圖、任務數，展開看所在地圖與接／交的任務；預設只列站在已開放地圖上的。六個分類互相串：所有小籤（怪物、道具、裝備、任務、NPC、地圖）點了都彈小卡，小卡裡再點就跳到那一列展開（地圖是走到世界地圖上的節點）。
- **世界地圖：** 地圖圖鑑不用列表，直接是客戶端的世界地圖插畫（`scripts/export_worldmap.py` 產生 `web/worldmap.json` 與 `web/worldmap/` 的圖，要先跑過 `scripts/export_worldbook.py`）。從總圖點島進區域，再點奇幻村這種子地圖（點該區的粉色節點也會直接進去），上方的路徑可以回上一層。滑鼠移到節點顯示是哪張地圖、幾張、怪物等級，點一下在旁邊看小地圖（標出 NPC 站位與傳送點，點標記彈小卡）、怪物（含生成點數）、NPC、相鄰地圖與回程地圖；手機點一下就好。灰色節點是還沒開放的地圖，客戶端沒有它們的名字，只有部分節點有標題。客戶端沒畫節點（或只算在上一層的總節點裡，例如巨人之林）、但有傳送點連回節點地圖的（隱密之地、隱藏地圖…）依傳送點關係一張補成一個紫色菱形，紫色實線照實際的傳送點連起來（隱密之地接隱密之地也是），位置只是示意；連不回去的（靠 NPC 或腳本進去的副本、自由市場…）收在地圖下面，也搜得到。搜尋比對地圖、區域、怪物、NPC 與節點標題，「目前地圖」一鍵走到讀到的那張並標上位置。
- **小浮窗：** Chrome / Edge 會開成一直置頂的小視窗，可以疊在遊戲上，經驗與楓幣（楓幣/hr、目前楓幣、總累計）都看得到。它只複製主頁面已經顯示的文字，不另外計算。上方的圖示按鈕可以停止、暫停、重置、縮小或關閉。縮小後只留狀態燈、經驗速率、升級倒數與楓幣速率。其他瀏覽器會退回一般彈出視窗，不會置頂。

讀不到數字時，展開頁面最下方的「診斷」，會放大顯示程式實際看到的像素。

## 時裝紙娃娃

跟練功助手、圖鑑同一層的分頁。選膚色、髮型、臉型與時裝（帽子、臉飾、眼飾、耳環、上衣、套服、褲裙、鞋子、手套、盾牌、披風、武器），角色在瀏覽器裡即時疊出來並播放動畫：站立、走路、警戒、跳躍、飛行、坐下、趴下、爬梯子、爬繩子、治療，加上 21 種攻擊（單手揮、雙手揮、長柄揮、單手刺、雙手刺、射擊與趴下刺）。時裝武器的武器類型跟遊戲一樣：武器有 `exceptLinkCashWeaponData` 的只能當自己有圖的類型，沒有的照客戶端 `LinkCashWeaponData` 什麼類型都能用（借 30 那組圖）。換武器時沿用上次選的類型，不支援就用第一個；每個類型會用的攻擊姿勢是匯出時從一般武器統計的，不用的、或這件武器沒畫的攻擊標成虛線。分類最左邊的「全部」把髮型、臉型、各類時裝放在一起搜尋。髮型、臉型的顏色與膚色在搜尋框旁的「調色盤」裡換（左邊是膚色、臉型、髮型合起來的預覽，右邊髮型、臉型各一框選顏色與混色，最下面是膚色；清單裡的髮型、臉型縮圖也跟著換成那個顏色與混色，縮圖每個顏色一張 `hair<色>.png`、`face<色>.png`），也可以選一個「混色」，跟遊戲的混合染髮、混合瞳色一樣以 50：50 疊上同款式的另一個顏色。限定性別的會在格子右上角標 ♂ / ♀：時裝跟遊戲一樣看編號千位數（0 男、1 女）；髮型、臉型客戶端沒有性別資料，照 maplestory.io 台版資料每段編號的 `requiredGender`（最早那批髮型 30、31、40、41 與臉型 20、21 不限）。背景可以換成購物商場試穿的幾張。抓資料、抓剛換上那幾件的圖時，預覽畫面整塊蓋一層「載入中」的遮罩。穿著的時裝列在畫布左邊，點 ✕ 脫掉；「隨機」每個部位各抽一件時裝、髮型與臉型也各抽一款（膚色、髮色與瞳色不動；套服跟上衣＋褲裙二選一，抽到雙手武器就不拿盾牌，性別篩選開著就只抽那個性別能用的）；畫布下面有四個儲存格，右上角存目前的造型、點格子套用，「恢復原狀」回到套用中的那格。打開「鍵盤模式」可以用鍵盤操作角色：← → 走路、↓ 趴下、↑ 爬梯子或繩子（要碰到）、Ctrl 攻擊（照武器類型的招式輪流，每種三次，打完警戒 5 秒）、Alt 跳躍、X 坐下；關著時用「展開動作面板」挑動作。穿搭、儲存格都記在瀏覽器裡。

資料是 `scripts/export_avatar.py` 從客戶端匯出的快照：`web/avatar.json` 是目錄，`web/avatar/` 裡是幾十個 `.bin` 包（每件的部位表與圖集接在一起，`avatar.json` 記每件在哪一包哪一段），網頁用 Range 只抓選到的那件；`back<N>.<hash>.webp` 是購物商場試穿視窗的背景（`avatar.json` 的 `backs`），畫布就用它的大小。網站上這些資料不跟主站一起部署（太大會讓 GitHub Pages 卡住），而是由 `scripts/publish_avatar.py` 推到另一個 repo `PrisonDiary-avatar`，從它的 Pages 讀；`update_data.bat` 發布時紙娃娃有變會自動推。部位靠客戶端的骨架點對位；圖放在特效裡的時裝（翅膀、跟在旁邊的小動物、頭上飄的裝飾）沒有骨架點，照客戶端每個動作的 `pos` 定位：是 1 就把圖的原點對在眉心，不是就水平對肚臍、垂直對腳底，前後也照那個動作的 `z`（這兩個值另外匯成 `web/avatar-effects.json`，`scripts/export_avatar_effects.py`；規則是拿 maplestory.io 畫的圖對出來的）；但客戶端找不到圖層前後與圖層佔用欄位的表，所以 `src/mapleexp/avatar.py` 的 `ORDER` 與網頁的 `dollHidden` 是依名稱手排的，少數搭配可能跟遊戲裡不一樣。匯出時遇到不認得的圖層會印出來提醒補進 `ORDER`。

## 更新圖鑑資料

圖鑑都是客戶端資料的快照，遊戲改版不會自動更新，要在裝了遊戲的電腦上匯出。匯出圖片要 `UnityPy` 與 `lz4`，這兩個套件在剛出的 Python 版本上常常還裝不到（3.15 在 Windows 上就是），那就另外開一個裝得到的版本的環境來跑匯出腳本（例如 `uv venv .venv313 --python 3.13`，再 `uv pip install --python .venv313/Scripts/python.exe UnityPy lz4 Pillow numpy`）`update_data.bat` 有 `.venv313` 就用它，沒有才用 `.venv`；選到的環境匯入不了 `UnityPy` 與 `lz4` 會直接停下來說明，不會跑到一半才失敗。更新遊戲後雙擊根目錄的 `update_data.bat`：照順序重跑所有匯出、列出每份圖鑑的數量變化（變少的會警示）、跑測試，輸入 `y` 才升版號、提交並推送到 main，之後自動部署。工作目錄有未提交的修改或不在 main 時不會開始。

部署（`.github/workflows/pages.yml`）會把 `web/mobs/`、`web/npcs/`、`web/minimaps/` 的兩千多張圖用 `scripts/pack_images.py` 併成十幾個 `.bin` 包，網站上只放這些包與記位置的 `packs.json`，網頁用 Range 只抓要的那張：GitHub Pages 檔案一多就常卡在 `syncing_files`。repo 裡還是散檔，本機開發沒有 `packs.json`，網頁就直接讀散檔。

## 排行榜後端

`server/app.py` 是一支只用標準函式庫的 Python 程式（3.11 以上），資料是一個 SQLite 檔。它不隨網站部署，獨立跑在家裡的一台 Raspberry Pi 3 上，經 Tailscale Funnel 取得對外的 HTTPS 網址。沒有登入也沒有帳號：只收紀錄、算排行榜，不能把紀錄抓回去。它只出資料，畫面是網站上的「排行榜」頁籤。

### 架構

```
使用者的瀏覽器（GitHub Pages 上的 web/index.html）
   │  HTTPS，跨網域（後端回 Access-Control-Allow-Origin: *）
   ▼
Tailscale Funnel   https://prisondiary.tailcfc41e.ts.net
   │  Tailscale 的入口只轉送加密的連線，TLS 在主機上的 tailscaled 解開，
   │  再以 HTTP 連 127.0.0.1:8787，真正的來源位址放在 X-Forwarded-For
   ▼
server/app.py   systemd 使用者服務 prisondiary-api，聽 0.0.0.0:8787
   │  一條資料庫連線，所有讀寫加鎖排隊
   ▼
SQLite   ~/prisondiary-api/data/records.db
```

網站是 HTTPS，瀏覽器不讓它呼叫 HTTP 的後端，所以對外一定要經過通道。區網裡的電腦可以不經通道，直接呼叫 `http://<主機>:8787/api/...`。

### 目前的配置

| 執行環境 | 系統內建的 Python 3.13，不裝任何套件 |

### 程式的組成

程式全部在 `server/app.py` 一個檔裡，旁邊另外放一份名稱清單 `server/names.json`：

- `Names`：讀 `names.json`，裡面是狀態列可能顯示的職業（50 個，來自 `jobvocab.JOB_NAMES`）、網頁會上傳的地圖名稱（「地區 地圖」，來自 `web/mapvocab.json`）與不算排行榜的地圖（地圖圖鑑 `mark` 是 `GoddessTower` 的，也就是女神組隊任務雅典娜禁地那 24 個名字）。這份檔由 `scripts/export_server_names.py` 產生，`update_data.py` 更新圖鑑時會一起重跑；測試會檢查它跟來源對得上。`status_of()` 照這份清單判斷一筆紀錄算不算排行榜。

- `validate()`：把網頁傳來的一筆紀錄（camelCase）檢查過，轉成資料表的欄位；不合格的丟 `Invalid`，原因會回給網頁。`validate_look()` 檢查一套造型，只留認得的欄位；`owner_of()` 把瀏覽器的金鑰換成雜湊。
- `Store`：SQLite 的包裝。`add()` 存一批（順便算好 `status`）、`count()` 回筆數（`counted=True` 只數算排行榜的）、`boards()` 算三個個人榜（附榜上角色的造型）、`training()` 算練功榜、`set_look()` 設或拿掉一個角色的造型、`my_looks()` 列一把金鑰名下的角色。算好的結果快取 60 秒，有寫入或改了造型就清掉。沒有刪除：收下的紀錄要拿掉只能直接改資料檔。
- `RateLimiter`：每個 IP 每分鐘的請求數（固定視窗），只放在記憶體，重開就歸零。
- `client_ip()`：決定上傳者的 IP。連線來自本機（也就是通道）時才信 `CF-Connecting-IP` 或 `X-Forwarded-For`，直接連進來的人自己填的標頭不算數。
- `Handler`：路由與回應，跑在 `ThreadingHTTPServer` 上，每個連線一條執行緒，15 秒沒動靜就斷。正常的請求不寫 log，只留 400 以上的（journal 也在 SD 卡上）。

### API

| 方法與路徑 | 內容 | 回應 |
| --- | --- | --- |
| `POST /api/records` | `{"key", "records": [...]}`，1 到 100 筆；`key` 是瀏覽器的金鑰，可以不帶（舊版網頁） | `200`，`{"accepted": [uid], "rejected": [{"uid", "reason"}], "uncounted": [{"uid", "reason"}]}`；已經有的 uid 也算 accepted；`uncounted` 是收下了但不算排行榜的（也在 `accepted` 裡），`reason` 是原因 |
| `POST /api/records/rename` | `{"key", "from": [舊名字…], "to"}`；`from` 1 到 20 個 | `200`，`{"renamed": 筆數}`：只改這把金鑰名下、角色叫 `from` 其中之一的紀錄，舊名字的造型是這把金鑰設的、新名字還沒有造型就一起搬 |
| `POST /api/looks` | `{"key", "character", "look"}`；`look` 給 `null` 是拿掉 | `200`，`{"ok": true}`；這把金鑰沒傳過那個角色的紀錄回 `403` |
| `POST /api/looks/mine` | `{"key"}` | `{"characters": [{"character", "look"}]}`：這把金鑰名下的角色與各自目前的造型（沒設是 `null`） |
| `GET /api/leaderboard` | `?days=7&limit=50`；`days` 不給就是全部，`limit` 最多 200 | `{"days", "exp": [...], "rate": [...], "level": [...], "looks": {角色: 造型}}` |
| `GET /api/training` | `?days=7&job=法師&level=35&limit=100`；都可以不給，`level` 給區間裡任何一級都行 | `{"days", "jobs": [...], "levels": [...], "rows": [...]}` |
| `POST /api/glyphs` | `{"key", "glyphs": [...]}`，1 到 200 個；每個是 `{kind, char, h, w, bits, value, frame, source, version}`，`key` 可以不帶 | `200`，`{"accepted": 個數, "rejected": 個數}`；同一個瀏覽器回報過的同一個字形也算 accepted。只收不出，沒有讀回來的路徑 |
| `POST /api/snapshots` | `{"key", "kind", "uid", "reason", "version", "state", "crops"}`；`kind` 是 `segment`（一段紀錄，`uid` 是那筆紀錄）或 `anomaly`（一直讀不到東西，`reason` 是讀不到什麼）；`crops` 是 `{名稱: PNG 的 base64}`，最多 16 塊、每塊 96 KB；整個請求最多 256 KB | `200`，`{"code"}`；一個瀏覽器一天超過 300 份回 `429` |
| `POST /api/reports` | `{"key", "version", "note", "state", "log", "crops", "frame"}`；`frame` 是整張畫面的 JPEG（base64，最多 4 MB），`note` 最多 2000 字、`log` 最多 30000 字；整個請求最多 6 MB | `200`，`{"code", "relayed"}`：`relayed` 是有沒有設 Discord 轉發；一個瀏覽器一天超過 30 次回 `429` |
| `GET /api/health` | | `{"ok": true, "records": 筆數, "counted": 算排行榜的筆數}` |
| `GET /` | | `302` 轉去網站的排行榜頁籤 |
| `POST /api/records/delete`、`DELETE /api/records/<uid>` | v0.33 以前的網頁刪紀錄時會叫 | `204`，但什麼都不刪；留著是因為舊網頁收到錯誤會一直重試、後面的紀錄也傳不上來 |

個人榜（`/api/leaderboard`）三個都是每個角色一列：`exp` 是總經驗（那個角色所有紀錄的經驗加起來，附最高等級、活躍時間、筆數），`rate` 是最高效率（EXP / hr 最高的那一筆，附那一筆的等級與地圖），`level` 是最高等級。職業取該角色最近一筆有讀到職業的。`looks` 是這次回應裡出現的角色中有設造型的（網頁的頒獎台畫全身、名單畫頭像）。

練功榜（`/api/training`）是每個「地圖 × 職業 × 等級區間」一列：把同一組的紀錄合起來，總經驗 ÷ 總活躍時間，效率高的在前，附累計活躍時間、紀錄數、角色數。等級每 10 級一個區間（1–10、11–20…）；地圖用名字分，沒讀到地圖、職業或等級的紀錄不算。`jobs` 與 `levels` 是這段期間有資料的職業與區間起點，給網頁做篩選的下拉選單。這個榜不帶任何角色名字。

兩個榜都只看「算數」的紀錄（`status` 是空字串）。一筆紀錄要算數，除了收得下（有角色名字、活躍滿 10 分鐘、格式對），還要：

1. 有等級；
2. 職業在合法清單裡（辨識程式配不上清單時會照 OCR 原文存，例如 `搶騎兵`）；
3. 地圖名稱在合法清單裡（辨識程式一定挑清單裡的一張，不在清單裡的是壞資料或舊版網頁；沒讀到地圖名稱也不算）；
4. 不是女神組隊任務的地圖：解任務拿的經驗不是練功。

不算的照樣存著，原因記在 `status`（`沒有等級`、`沒有職業`、`職業不在清單裡`、`沒有地圖名稱`、`地圖不在清單裡`、`女神組隊任務的地圖`），之後可以直接查資料檔找出是哪裡辨識錯，例如：

```bash
python3 -c "import sqlite3; db = sqlite3.connect('prisondiary-api/data/records.db'); [print(*r) for r in db.execute(\"SELECT status, character, job, level, map_name, datetime(end_at / 1000, 'unixepoch', 'localtime') FROM records WHERE status <> '' ORDER BY end_at DESC\")]"
```

服務每次啟動都照目前的 `names.json` 把每一筆的 `status` 重算一次，所以清單改了（客戶端加了新地圖、要多排除哪張地圖），舊紀錄也會跟著進出排行榜。

uid、IP 與金鑰（連雜湊）不會出現在任何回應裡。

### 資料表

`records` 一筆紀錄一列：

| 欄位 | 內容 |
| --- | --- |
| `uid` | 主鍵。網頁從紀錄內容算出來的指紋，排成 UUID 的樣子 |
| `character`、`job`、`level` | 角色、職業（可以是空的）、等級（可以沒有） |
| `map_id`、`map_name` | 地圖的像素指紋與名字 |
| `start_at`、`end_at` | 起訖時間（毫秒） |
| `cum_net`、`active_sec`、`idle_sec` | 累計經驗、活躍秒數、閒置秒數 |
| `ip`、`received_at` | 上傳者的 IP、後端第一次收到的時間（毫秒） |
| `owner` | 傳這筆紀錄的瀏覽器：金鑰的 SHA-256。這一欄加上去以前收的紀錄是空的，等那個瀏覽器下次開頁重傳時補上 |
| `status` | 空字串是算排行榜；不然是不算的原因（見上面 API 那一節）。每次啟動照 `names.json` 重算 |

索引有 `(character, end_at)`、`(end_at)` 與 `(owner, character)`。舊的資料檔在服務啟動時會自動補上 `owner` 與 `status` 欄。

`snapshots` 一份診斷快照或問題回報一列，內容放在資料檔旁邊的 `snapshots/<代碼>/` 資料夾（`state.json`、各塊裁切圖 `*.png`，回報另外有 `frame.jpg` 與 `report.txt`）：

| 欄位 | 內容 |
| --- | --- |
| `code` | 主鍵，六個字的代碼（不用 0、O、1、I），也是資料夾名稱 |
| `kind` | `segment`、`anomaly` 或 `report` |
| `uid` | `segment`：那段紀錄的 uid，可以跟 `records` 對起來 |
| `reason`、`note` | `anomaly` 讀不到什麼；`report` 使用者寫的描述 |
| `character`、`version` | 當時讀到的角色、網頁版本 |
| `reporter`、`ip`、`created_at` | 瀏覽器金鑰的雜湊（沒帶金鑰的是 `ip:` 加 IP）、IP、收到的時間（毫秒） |
| `bytes`、`files` | 資料夾裡的檔案多大、有哪些檔 |

自動快照留 30 天、回報留 180 天，每次收到新的時清一次；全部超過 300 MB 就從最舊的刪，自動快照先刪、回報最後。

查一筆不算排行榜的紀錄當時的畫面：

```bash
python3 -c "import sqlite3; db = sqlite3.connect('prisondiary-api/data/records.db'); [print(*r) for r in db.execute(\"SELECT s.code, r.status, r.character, r.job, r.level, r.map_name FROM records r JOIN snapshots s ON s.uid = r.uid WHERE r.status <> '' ORDER BY r.end_at DESC\")]"
scp -r <使用者>@<主機>:prisondiary-api/data/snapshots/<代碼> .
```

問題回報另外轉發到 Discord（webhook，一則訊息：代碼、版本、角色｜職業｜等級｜地圖、描述，附件是整張畫面、`report.txt`（描述、狀態與 log）與最多 8 塊裁切圖；描述裡的 `@everyone` 不會真的通知）。webhook 網址放在 `prisondiary-api/discord_webhook.txt`（只有一行網址，不要進版本控制）或環境變數 `PRISONDIARY_DISCORD_WEBHOOK`，改了要重啟服務；啟動時的第一行 log 會寫有沒有設。轉發在背景做，失敗重試一次，還是失敗只寫一行 log，回報照樣存在主機上。

`looks` 一個角色一列，有設造型的才有：

| 欄位 | 內容 |
| --- | --- |
| `character` | 主鍵，角色名字 |
| `look` | 造型，一段 JSON：`skin`、`hair`、`face`、`mix`（髮色與瞳色的混色）、`worn`（部位 → 時裝編號）、`group`（武器類型） |
| `owner`、`ip`、`updated_at` | 最後一次是哪把金鑰、從哪個 IP、什麼時候設的 |

`glyphs` 一個瀏覽器回報的一個字形一列（網頁靠 OCR 學會的數字字形）：

| 欄位 | 內容 |
| --- | --- |
| `kind` | `meso`（楓幣框）或 `level`（等級方塊） |
| `char` | 哪個數字，`0`～`9` |
| `h`、`w`、`bits` | 字形的高、寬與遮罩：逐列攤平、每 8 格一個位元組（`numpy.packbits`）再 base64，跟 `builtin_templates.json` 同一種寫法 |
| `reporter` | 回報的瀏覽器：金鑰的 SHA-256；沒帶金鑰的是 `ip:` 加 IP |
| `value` | 學到它的時候 OCR 讀出來的整個數字 |
| `frame_w`、`frame_h` | 辨識用的畫面大小（遊戲被放大顯示時是縮回去的大小） |
| `source_w`、`source_h` | 分享進來的原始畫面大小 |
| `version`、`ip`、`received_at` | 網頁版本、IP、收到的時間（毫秒） |

主鍵是 `(kind, char, h, w, bits, reporter)`：同一個瀏覽器回報同一個長相只記一次，所以「有幾個 reporter 回報同一個長相」就是有幾台電腦學到它。服務啟動時 `CREATE TABLE IF NOT EXISTS` 會自動建這張表，舊的資料檔不用另外處理。

整理時直接讀資料檔，例如列出每個長相有幾台電腦回報：

```bash
python3 - <<'PY'
import sqlite3
db = sqlite3.connect('prisondiary-api/data/records.db')
sql = """SELECT kind, char, h, w, bits, COUNT(*) AS n, GROUP_CONCAT(DISTINCT frame_w || 'x' || frame_h)
         FROM glyphs GROUP BY kind, char, h, w, bits ORDER BY kind, char, n DESC"""
for row in db.execute(sql):
    print(*row)
PY
```

### 重複與刪除

後端只靠 `uid` 認重複，內容不比對：`INSERT ... ON CONFLICT (uid) DO NOTHING`，同一個 `uid` 再來幾次都只有一筆，IP 與收到時間留第一次的。網頁每次開啟都會把手上的紀錄整批重傳，靠的就是這個；`uid` 由網頁的 `recordUid()` 從紀錄編號、角色、起訖時間、經驗算出來，同一筆不管重傳幾次、在哪個分頁算都一樣。

收下的紀錄不刪：使用者在網頁的歷史紀錄裡刪掉一筆、全部清除，或把上傳關掉，後端的都留著。沒有對外的刪除功能，真的要拿掉某一筆（例如明顯造假的）只能在主機上直接改資料檔。

### 金鑰與造型

沒有登入，但「誰能改這個角色的造型」需要一個依據：每個瀏覽器第一次上傳時自己產生一把金鑰（一串亂數，存在 localStorage 的 `mapleexp.syncKey`），之後每次上傳都帶著，後端把它的雜湊記在收下的每筆紀錄上（`owner`）。先傳的人是主：已經有主的紀錄，別人再重傳同一筆不會改。這個功能上線前收的紀錄沒有主，網頁每次開頁都會整批重傳，所以原本的使用者下次開頁就自動認領完。

一把金鑰只要名下有那個角色的任何一筆紀錄，就能設或拿掉那個角色的造型；同一個角色在兩台電腦都有紀錄，兩邊都能改，後設的蓋掉先設的。清掉網站資料金鑰就沒了，新的金鑰要等傳上去一筆那個角色的新紀錄才有資格。這擋不了有心人（偽造一筆同名的紀錄就有資格），跟排行榜的數字本身一樣只防君子；`looks` 記著最後是哪把金鑰、哪個 IP 設的，出事時查得到。

造型只是零件編號，後端只檢查格式（整數、範圍、部位名稱是英文字母、最多 24 個部位），不管那個編號存不存在：畫的是網頁，遇到不認得的編號（例如下一版客戶端拿掉的時裝）就當作沒穿。因為不收圖片，沒辦法拿排行榜放任意的圖。

### 限制

- 每個 IP 每分鐘最多 120 個請求，超過回 `429`。
- 一個請求的內容最多 128 KB，一批最多 100 筆紀錄或 200 個字形。
- 字形只收 `0`～`9`、邊長 1 到 40、`bits` 的長度要跟 `h × w` 對得上、`value` 裡要有那個數字、畫面大小 1 到 10000。
- 資料檔超過 200 MB 或磁碟剩不到 100 MB 就不再收新紀錄，回 `507`；排行榜照常。
- 活躍不滿 10 分鐘的紀錄不收（網頁連存都不存）；這個門檻加上去以前收下的短紀錄，服務啟動時會清掉。
- 每筆紀錄擋掉格式不對與明顯不可能的值：角色最多 24 字、等級 1 到 300、時間不早於 2020 年也不晚於現在加一天、活躍與閒置各不超過 30 天、經驗是正數且不超過 10 的 13 次方。
- 數字是瀏覽器自己算好傳上來的，上面這些擋不了有心造假。

### 安裝、更新與維護

第一次安裝照 `server/prisondiary-api.service` 開頭的說明做，再在主機上裝 Tailscale、登入、執行 `tailscale funnel --bg 8787`（第一次會給一條連結，要到 Tailscale 後台同意啟用 Funnel）。

程式或名稱清單改了要自己複製過去再重啟，服務中斷幾秒，網頁傳不上去的會自己再試。`names.json` 一定要跟 `app.py` 放在同一個資料夾，沒有它服務起不來：

```bash
scp server/app.py server/names.json <使用者>@<主機>:prisondiary-api/
ssh <使用者>@<主機> systemctl --user restart prisondiary-api
```

網頁與後端都要改的時候先更新後端：舊網頁還會被瀏覽器快取一陣子，後端要同時認得新舊兩種請求。

| 要做的事 | 指令（在主機上） |
| --- | --- |
| 看服務狀態 | `systemctl --user status prisondiary-api` |
| 看 log | `journalctl --user -u prisondiary-api` |
| 看目前筆數 | `curl http://127.0.0.1:8787/api/health` |
| 看通道 | `tailscale funnel status` |
| 備份資料檔 | 複製 `records.db`，服務跑著的時候要連同 `-wal` 檔一起，或用 `python3 -c "import sqlite3; sqlite3.connect('records.db').backup(sqlite3.connect('備份檔'))"`（主機上沒有 `sqlite3` 指令） |

本機開發時不用改程式：`python server/app.py` 起一個只聽本機的後端（資料檔預設在 `server/data/records.db`），再開 `http://localhost:8765/?api=http://127.0.0.1:8787`，網頁就會指到它（記在瀏覽器裡，`?api=` 取消；只有本機開的頁面能這樣改）。
