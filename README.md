# 服刑日誌（網頁版）

楓之谷：經典版的經驗值計算器，整個在瀏覽器裡跑。用瀏覽器的「分享視窗」看遊戲畫面，
讀狀態列的經驗值，算出 EXP/hr 與升級剩餘時間。不用安裝程式，也完全不接觸遊戲程序：
不注入、不讀記憶體、不攔封包，只看分享出來的畫面。

這個 Repo 從 [MapleExpTool](https://github.com/andy971029/MapleExpTool) 拆出來，只留網頁版。
辨識與追蹤邏輯和桌面版是同一套 Python 程式碼，用 [Pyodide](https://pyodide.org/) 在瀏覽器裡執行。

## 使用

直接用 Chrome 或 Edge 開 https://andy971029.github.io/PrisonDiary/ ，什麼都不用裝。
每次 push 到 main，GitHub Actions 會先跑測試，通過才重新打包並發布。

### 在自己電腦跑

需要 Python 3.11 以上（只用來打包與開本機伺服器）和 Chrome 或 Edge。

```powershell
git clone https://github.com/andy971029/PrisonDiary.git
cd PrisonDiary
.\web\serve.cmd
```

1. 用 Chrome 或 Edge 開 http://localhost:8765/ 。
2. 等按鈕從「載入 Python 環境…」變成「分享遊戲視窗」。第一次要下載約 10 MB 的 Pyodide 與 numpy，之後瀏覽器會快取。
3. 按「分享遊戲視窗」，在對話框選「視窗」分頁、挑遊戲視窗。
4. 想邊玩邊看，就按「開啟小浮窗」。

## 功能

- **經驗值與速率：** 用字元模板比對讀經驗值，不用 OCR。實測 OCR 讀數字幾乎全錯。
- **楓幣收益：** 背包視窗開著時讀背包底部的楓幣欄位，算楓幣/hr、最近 10 分鐘與整場的累計。背包可以放在畫面任何位置，程式會自己找（認「楓幣框＋楓葉點數框」上下成對的白框）；拖走或關掉後會重新找。背包關著的時間不計入，短暫被滑鼠擋住則照算。數字用模板比對，沒看過的字形先交給 OCR 讀、讀對了再學起來。
- **角色、職業、等級、地圖：** 用 Tesseract.js 辨識。中文走 `chi_tra`，等級的數字走英文模型。語言檔第一次要下載幾十 MB，之後存在瀏覽器的 IndexedDB。
- **歷史紀錄：** 以「角色 × 地圖」為一段，結算時確認才存進瀏覽器的 localStorage。活躍不滿 10 分鐘的段不記錄：結算時直接丟掉（結算視窗會說有幾段），以前存下來的短紀錄開頁時也會移除。只存在這個瀏覽器，可以匯出 JSON。
- **排行榜：** 上方的「排行榜」頁籤（網址 `#rank`），資料是大家上傳的練功紀錄，由後端（`server/app.py`）算好、網頁呼叫 API 抓來顯示。「個人排行榜」分總累計經驗、最高效率、等級三塊，每塊上面是前三名的頒獎台，下面是完整名單；頒獎台上站的是玩家自己設的紙娃娃造型，名單每一列前面是同一套造型的頭像，沒設的是空的剪影；這個瀏覽器傳過紀錄的角色（自己的角色）會用琥珀色的框標出來，點它的紙娃娃或頭像會切到紙娃娃頁籤、把「排行榜造型」鈕亮起來；「練功排行榜」（`#rank/train`）把同一張地圖、同一個職業、同一個 10 級區間的紀錄合起來算平均 EXP / hr，可以依職業與等級區間篩選，看哪裡好練。兩個都能切全部、近 30 天、近 7 天；向後端抓資料的時候整張卡片會蓋一層「載入中」的遮罩。版面跟圖鑑一樣不出現外層捲軸：卡片撐滿視窗剩下的高度，名單與表格在卡片裡面捲。上傳是自動的：後端網址（`web/index.html` 的 `SYNC_API`）有設的時候，每次開啟網頁把手上的歷史紀錄整批傳一次，每次儲存紀錄再傳新的那幾筆；讀不到角色名字的不傳，只留在瀏覽器（活躍不滿 10 分鐘的段連歷史紀錄都不進）。上傳的是角色、職業、等級、地圖、起訖時間、經驗與秒數，後端另外記下上傳者的 IP（不對外顯示）；結算視窗會先講明，不想上傳就到「設定」關掉「上傳練功紀錄」。排行榜造型在紙娃娃頁籤設：按「排行榜造型」，從這個瀏覽器傳過紀錄的角色裡挑一個，把目前的造型套上去（一個角色一套，也可以拿掉）。傳上去的是造型的零件編號（膚色、髮型、臉型、混色、各部位的時裝、武器類型），不是圖片，排行榜再用紙娃娃的資料把站姿畫出來。後端靠瀏覽器自己產生的一把金鑰認「這個角色的紀錄是不是這個瀏覽器傳的」：同一個角色在兩台電腦都有紀錄就兩邊都能改、後設的蓋掉先設的；清掉網站資料金鑰就換一把新的，要等下次再上傳那個角色的紀錄才能再設。沒有登入也沒有帳號，所以只是「傳上去」：不能換一台電腦把紀錄抓回來，傳上去的也不會因為在歷史紀錄裡刪掉、全部清除或關掉開關而從排行榜消失。後端只靠每筆紀錄的 `uid` 認重複：`uid` 是網頁從紀錄內容（紀錄編號、角色、起訖時間、經驗）算出來的指紋，同一筆不管重傳幾次都是同一個，後端已經有就不再存。後端連不上時紀錄先留著，五分鐘後、下次開頁或恢復連線時再傳。數字是瀏覽器算好傳上去的，後端只擋格式不對與明顯不可能的值。
- **經驗加倍試算：** 經驗收益右上角可以選「無加倍」「1.5 倍」「2 倍」（預設無加倍），速率、累計與倒數都照倍數顯示，不影響歷史紀錄。
- **神聖祈禱倒數：** 不用按任何按鈕，分享畫面後就會每格到畫面右上角第一排 buff 裡找神聖祈禱的圖示，視窗模式（buff 在遊戲視窗頂端、不在畫面頂端）找不到時，隔幾秒再到畫面上半部大範圍找一次（連續找不到就越隔越久，最長 30 秒），找到後就跟著位置走，圖示不見再出現時先看原來那一列，讀它左下角的剩餘時間。白色數字代表分鐘，顯示「1m+」；剩不到一分鐘會變成黃色的秒數。數字不靠文字辨識：0～9 的字形都內建（取自分享串流的實際畫面），0～59 每個數字該長什麼樣整塊拿去跟畫面比亮度、取最像的，分不出高下就這一格不讀，所以兩個數字黏在一起或畫面糊掉時，不會只讀到半個數字。每讀到一次秒數就算出一個「結束時刻」，最近五格裡有三格算出同一個時刻才採用，偶爾讀錯的那一格跟別格對不上、自然不算數；白色剛變黃色的那一刻剩 60 秒，所以第一格黃色就開始倒數。兩次截圖之間由網頁自己往下數。圖示快結束時會由下往上變灰，比對時每一列各自正規化，所以灰掉的部分照樣認得出來。寵物重放後自然接到下一輪，不用設定祈禱等級。剩下秒數到「警示倒數」時會用設定好的顏色閃爍與音效提醒；祈禱自然結束（寵物沒重放）也會提醒：歸零後圖示還會留幾秒、上面沒有數字、一閃一閃地消失，這時算「結束了」，不會被當成一分鐘以上。圖示暫時找不到（滑鼠移過去跳出說明、被視窗或特效擋住）時倒數照走、不會消失，一路被擋到時間到也照樣提醒。沒用祈禱時按鈕只顯示「—」。點一下祈禱鈕可以關掉提醒（虛線框、圖示變灰、多一個紅色靜音鈴鐺），倒數照樣顯示，再點一下打開。電腦比較吃力或沒在用祈禱時，可以在「設定」裡關掉「辨識神聖祈禱」，就完全不找圖示，按鈕和其他祈禱設定也會一起藏起來。覺得倒數不準時，到「設定」按「匯出樣本」：工具一直留著最近 2 分鐘畫面右上角 buff 那一排的原始像素，連同每一格讀到的秒數與當時顯示的倒數，存成一張 PNG（每格一列，同一份資料另外以 JSON 放在 PNG 的 `tEXt` 區塊 `prayer-samples`），把原檔傳給作者就能重現問題。這次分享看到過祈禱圖示就只存那一列附近（352×48），還沒看到過就存畫面右上角 640×112，所以找不到圖示的情況也查得出來。
- **女神組隊任務小工具：** 主頁有一塊「女神組隊任務」，四關的圖和工具一次排開：休息室（每天要蒐集的唱片，依台北時間標出今天）、封印之室（照著按 NPC 說的 0／1，一步步排出台階人數，最多 5 次）、倉庫（地圖上標好紅獨角獅出現的順序）、中央塔（參考圖），地圖名稱讀到哪一關就把那關框起來。小浮窗角色那一行右邊的「女神」鈕，按下去把經驗、楓幣換成同樣的小工具（用分頁切關卡，進到關卡會自動選好那一關），再按「經驗」換回來；封印之室的進度兩邊共用。
- **功能頁籤：** 頂列左邊標題底下切換「練功助手」（上面這些）與「圖鑑」（怪物、道具、裝備、任務、NPC、地圖）；跟讀畫面有關的東西都在頂列右邊：控制鈕一列、底下是讀到的角色、職業、等級與地圖，在哪一頁都看得到，分享照跑。選了哪頁記在瀏覽器裡，網址加 `#book` 直接開圖鑑。
- **怪物圖鑑：** 從遊戲客戶端的資料檔匯出的快照（`scripts/export_monsterbook.py` 產生 `web/monsterbook.json` 與 `web/mobs/` 的怪物圖，客戶端改版重跑一次；匯出圖要另外 `pip install UnityPy`）。每隻怪的站姿圖（列表是縮圖，展開看大圖，太大的 Boss 縮到 256 像素）、等級、HP、MP、EXP、EXP/HP、物防、魔防、命中、迴避，加上圖鑑卡上列的掉落物與出現地圖（沒有機率，掉落率在伺服器端）。出現地圖不是抄圖鑑卡，是從客戶端的地圖資料（每張地圖的怪物生成清單）算的：客戶端只放已開放區域的地圖，所以沒出現在任何一張地圖的怪就是還沒開放的（武陵、童話王國那些），預設不列，要看打開「含未開放的怪」，展開時會列圖鑑卡上寫的、以後會出現的地方。搜尋同時比對怪物名、型態、掉落物名與地圖名，可以用等級範圍篩、只看「目前地圖的怪」（讀到地圖名稱後才能按），點一列展開圖鑑說明、掉落物與出現地圖；掉落物是帶圖示的小籤，裝備依職業、道具依類別分組，點一個彈出那件東西的小卡（數值、效果、說明、會掉的怪）。預設只列有圖鑑卡的野怪，任務、活動、召喚物要打開「含沒有圖鑑卡的怪」。
- **道具與裝備圖鑑：** 圖鑑分頁裡再分「怪物」「道具」「裝備」。道具與裝備也是客戶端資料的快照（`scripts/export_itembook.py` 產生 `web/itembook.json`，圖示打包成 `web/icons/` 的兩張圖集，要先跑過怪物圖鑑的匯出）。裝備列需求等級、職業、STR／DEX／INT／LUK 需求、攻擊、防禦、其他加成、可升級次數，可以用類別、職業、等級範圍篩；道具列類別、效果（藥水回復量、料理增益與持續時間、卷軸成功率與加成）、等級、商店價。兩邊都有「會掉的怪」：從怪物圖鑑卡反查、只算已開放的怪，展開後是帶怪物縮圖的小籤，點一個彈出那隻怪的小卡（數值、說明），可以只看怪物會掉的；另有「任務獎勵」：接得到的任務會給這個當獎勵的，點一個彈出那個任務的小卡，也可以只看任務給的。商店賣的、NPC 製作的客戶端裡沒有資料（製作配方在伺服器端）。現金裝與現金道具不列。
- **任務、NPC、地圖圖鑑：** 同樣是客戶端資料的快照（`scripts/export_worldbook.py` 一次產生 `web/questbook.json`、`web/npcbook.json`、`web/mapbook.json`、`web/npcs/` 的 NPC 站姿圖與 `web/minimaps/` 的小地圖，要先跑過怪物與道具圖鑑的匯出）。任務列區域、等級、職業、接任務的 NPC、EXP、楓幣、獎勵道具，展開看接／交任務的 NPC、前置與接續任務、要交的道具與要打的怪、獎勵（固定給、擇一、隨機，附職業與性別限制）與接任務前、進行中、完成後的說明；預設只列接得到的（接任務的 NPC 站在已開放的地圖上、活動沒結束）。NPC 列職稱、所在地圖、任務數，展開看所在地圖與接／交的任務；預設只列站在已開放地圖上的。六個分類互相串：所有小籤（怪物、道具、裝備、任務、NPC、地圖）點了都彈小卡，小卡裡再點就跳到那一列展開（地圖是走到世界地圖上的節點）。
- **世界地圖：** 地圖圖鑑不用列表，直接是客戶端的世界地圖插畫（`scripts/export_worldmap.py` 產生 `web/worldmap.json` 與 `web/worldmap/` 的圖，要先跑過 `scripts/export_worldbook.py`）。從總圖點島進區域，再點奇幻村這種子地圖（點該區的粉色節點也會直接進去），上方的路徑可以回上一層。滑鼠移到節點顯示是哪張地圖、幾張、怪物等級，點一下在旁邊看小地圖（標出 NPC 站位與傳送點，點標記彈小卡）、怪物（含生成點數）、NPC、相鄰地圖與回程地圖；手機點一下就好。灰色節點是還沒開放的地圖，客戶端沒有它們的名字，只有部分節點有標題。客戶端沒畫節點（或只算在上一層的總節點裡，例如巨人之林）、但有傳送點連回節點地圖的（隱密之地、隱藏地圖…）依傳送點關係一張補成一個紫色菱形，紫色實線照實際的傳送點連起來（隱密之地接隱密之地也是），位置只是示意；連不回去的（靠 NPC 或腳本進去的副本、自由市場…）收在地圖下面，也搜得到。搜尋比對地圖、區域、怪物、NPC 與節點標題，「目前地圖」一鍵走到讀到的那張並標上位置。
- **小浮窗：** Chrome / Edge 會開成一直置頂的小視窗，可以疊在遊戲上，經驗與楓幣（楓幣/hr、目前楓幣、總累計）都看得到。它只複製主頁面已經顯示的文字，不另外計算。上方的圖示按鈕可以停止、暫停、重置、縮小或關閉。縮小後只留狀態燈、經驗速率、升級倒數與楓幣速率。其他瀏覽器會退回一般彈出視窗，不會置頂。

讀不到數字時，展開頁面最下方的「診斷」，會放大顯示程式實際看到的像素。

## 結構

```
web/
├── index.html        介面、歷史紀錄、小浮窗（JS）
├── bridge.py         在 Pyodide 裡跑的膠水層：canvas 畫面 → 辨識 → 追蹤 → JSON
├── mapvocab.json     地圖名稱清單快照，用來校正 OCR 讀到的地圖名
├── monsterbook.json  怪物圖鑑快照：數值、掉落物、出現地圖與名稱表
├── itembook.json     道具與裝備圖鑑快照：數值、效果、說明與掉落來源
├── questbook.json    任務圖鑑快照：條件、需求、獎勵、說明
├── npcbook.json      NPC 圖鑑快照：職稱、所在地圖
├── mapbook.json      地圖圖鑑快照：生成的怪、NPC、傳送點通往的地圖、小地圖標記
├── worldmap.json     世界地圖快照：節點座標與涵蓋的地圖、區域連結、層級
├── icons/            道具與裝備的圖示圖集（equips.png、items.png），JSON 記格子序號
├── mobs/             怪物站姿圖，一隻一張 PNG，檔名是怪物 ID
├── npcs/             NPC 站姿圖，一個一張 PNG，檔名是 NPC ID
├── minimaps/         小地圖，一張地圖一張 PNG，檔名是地圖 ID
├── worldmap/         世界地圖底圖（WebP）、區域與路線圖層、節點圖示
└── serve.cmd         打包 + 開本機伺服器
src/mapleexp/
├── vision/           二值化、切割、模板比對、定位、面板與身分辨識
├── core/             讀值解析、追蹤狀態機、統計、經驗表反推
├── gamedata.py       解客戶端的 UnityFS bundle，撈 JSON 字串表（地圖、怪物、物品名稱）
├── wzjs.py           解客戶端的 WZJS 二進位節點樹（舊版 .wz 搬過來的怪物數值、圖鑑）
├── spritesheet.py    解客戶端的圖集（哪一格圖在貼圖的哪裡），匯出怪物圖與道具圖示用
├── itembook.py       把裝備數值、道具效果、名稱表、掉落來源合成 web/itembook.json
```

## 時裝紙娃娃

跟練功助手、圖鑑同一層的分頁。選膚色、髮型、臉型與時裝（帽子、臉飾、眼飾、耳環、上衣、套服、褲裙、鞋子、手套、盾牌、披風、武器），角色在瀏覽器裡即時疊出來並播放動畫：站立、走路、警戒、跳躍、飛行、坐下、趴下、爬梯子、爬繩子、治療，加上 21 種攻擊（單手揮、雙手揮、長柄揮、單手刺、雙手刺、射擊與趴下刺）。時裝武器的武器類型跟遊戲一樣：武器有 `exceptLinkCashWeaponData` 的只能當自己有圖的類型，沒有的照客戶端 `LinkCashWeaponData` 什麼類型都能用（借 30 那組圖）。換武器時沿用上次選的類型，不支援就用第一個；每個類型會用的攻擊姿勢是匯出時從一般武器統計的，不用的、或這件武器沒畫的攻擊標成虛線。分類最左邊的「全部」把髮型、臉型、各類時裝放在一起搜尋。髮型、臉型的顏色與膚色在搜尋框旁的「調色盤」裡換（左邊是膚色、臉型、髮型合起來的預覽，右邊髮型、臉型各一框選顏色與混色，最下面是膚色；清單裡的髮型、臉型縮圖也跟著換成那個顏色與混色，縮圖每個顏色一張 `hair<色>.png`、`face<色>.png`），也可以選一個「混色」，跟遊戲的混合染髮、混合瞳色一樣以 50：50 疊上同款式的另一個顏色。限定性別的會在格子右上角標 ♂ / ♀：時裝跟遊戲一樣看編號千位數（0 男、1 女）；髮型、臉型客戶端沒有性別資料，照 maplestory.io 台版資料每段編號的 `requiredGender`（最早那批髮型 30、31、40、41 與臉型 20、21 不限）。背景可以換成購物商場試穿的幾張。穿著的時裝列在畫布左邊，點 ✕ 脫掉；畫布下面有四個儲存格，右上角存目前的造型、點格子套用，「恢復原狀」回到套用中的那格。打開「鍵盤模式」可以用鍵盤操作角色：← → 走路、↓ 趴下、↑ 爬梯子或繩子（要碰到）、Ctrl 攻擊（照武器類型的招式輪流，每種三次，打完警戒 5 秒）、Alt 跳躍、X 坐下；關著時用「展開動作面板」挑動作。穿搭、儲存格都記在瀏覽器裡。

資料是 `scripts/export_avatar.py` 從客戶端匯出的快照：`web/avatar.json` 是目錄，`web/avatar/` 裡是幾十個 `.bin` 包（每件的部位表與圖集接在一起，`avatar.json` 記每件在哪一包哪一段），網頁用 Range 只抓選到的那件；`back<N>.<hash>.webp` 是購物商場試穿視窗的背景（`avatar.json` 的 `backs`），畫布就用它的大小。網站上這些資料不跟主站一起部署（太大會讓 GitHub Pages 卡住），而是由 `scripts/publish_avatar.py` 推到另一個 repo `PrisonDiary-avatar`，從它的 Pages 讀；`update_data.bat` 發布時紙娃娃有變會自動推。部位靠客戶端的骨架點對位；但客戶端找不到圖層前後與圖層佔用欄位的表，所以 `src/mapleexp/avatar.py` 的 `ORDER` 與網頁的 `dollHidden` 是依名稱手排的，少數搭配可能跟遊戲裡不一樣。匯出時遇到不認得的圖層會印出來提醒補進 `ORDER`。

## 更新圖鑑資料

圖鑑都是客戶端資料的快照，遊戲改版不會自動更新，要在裝了遊戲的電腦上匯出。更新遊戲後雙擊根目錄的 `update_data.bat`：照順序重跑所有匯出、列出每份圖鑑的數量變化（變少的會警示）、跑測試，輸入 `y` 才升版號、提交並推送到 main，之後自動部署。工作目錄有未提交的修改或不在 main 時不會開始。

部署（`.github/workflows/pages.yml`）會把 `web/mobs/`、`web/npcs/`、`web/minimaps/` 的兩千多張圖用 `scripts/pack_images.py` 併成十幾個 `.bin` 包，網站上只放這些包與記位置的 `packs.json`，網頁用 Range 只抓要的那張：GitHub Pages 檔案一多就常卡在 `syncing_files`。repo 裡還是散檔，本機開發沒有 `packs.json`，網頁就直接讀散檔。

## 排行榜後端

`server/app.py` 是一支只用標準函式庫的 Python 程式（3.11 以上），資料是一個 SQLite 檔。它不隨網站部署，獨立跑在家裡的一台 Raspberry Pi 3 上，經 Tailscale Funnel 取得對外的 HTTPS 網址。沒有登入也沒有帳號：只收紀錄、算排行榜，不能把紀錄抓回去。它只出資料，畫面是網站上的「排行榜」頁籤。

### 架構

```
使用者的瀏覽器（GitHub Pages 上的 web/index.html）
   │  HTTPS，跨網域（後端回 Access-Control-Allow-Origin: *）
   ▼
Tailscale Funnel   https://prisondiary.tailcfc41e.ts.net
   │  Tailscale 的入口只轉送加密的連線，TLS 在主機上的 tailscaled 解開，
   │  再以 HTTP 連 127.0.0.1:8787，真正的來源位址放在 X-Forwarded-For
   ▼
server/app.py   systemd 使用者服務 prisondiary-api，聽 0.0.0.0:8787
   │  一條資料庫連線，所有讀寫加鎖排隊
   ▼
SQLite   ~/prisondiary-api/data/records.db
```

網站是 HTTPS，瀏覽器不讓它呼叫 HTTP 的後端，所以對外一定要經過通道。區網裡的電腦可以不經通道，直接呼叫 `http://<主機>:8787/api/...`。

### 目前的配置

| 項目 | 設定 |
| --- | --- |
| 主機 | Raspberry Pi 3 Model B（1 GB 記憶體、8 GB SD 卡），Raspberry Pi OS（Debian trixie，64 位元），文字模式開機，接有線網路 |
| 執行環境 | 系統內建的 Python 3.13，不裝任何套件 |
| 程式 | `~/prisondiary-api/app.py`，就是 repo 的 `server/app.py` |
| 服務 | systemd 使用者服務 `prisondiary-api`（`~/.config/systemd/user/prisondiary-api.service`，內容是 repo 的 `server/prisondiary-api.service`），不需要 root；`Restart=always`，隔 10 秒重啟；`loginctl enable-linger` 開著，開機就起來，不用等使用者登入 |
| 啟動參數 | `--host 0.0.0.0 --port 8787 --db ~/prisondiary-api/data/records.db`（不給 `--host` 時只聽 127.0.0.1） |
| 記憶體上限 | `MemoryHigh=64M`、`MemoryMax=96M`；平常用不到 30 MB，同一台機器上還有別的服務 |
| 資料檔 | `~/prisondiary-api/data/records.db`，SQLite 的 WAL 模式、`synchronous=NORMAL`（少寫幾次 SD 卡；斷電最多丟最後幾筆，不會壞檔） |
| 對外 | Tailscale 1.104（`tailscaled` 是系統服務，開機自動啟動）；`tailscale funnel --bg 8787` 把 `https://prisondiary.tailcfc41e.ts.net` 轉到 `http://127.0.0.1:8787`，設定記在 tailscaled 裡，重開機後自己恢復 |
| 網頁指向 | `web/index.html` 的 `SYNC_API` 填上面的網址；改成空字串時整個上傳功能是關的，設定裡的開關與「排行榜」頁籤也不會出現 |
| 備份 | 還沒有，資料只在 SD 卡上 |

### 程式的組成

全部在 `server/app.py` 一個檔裡：

- `validate()`：把網頁傳來的一筆紀錄（camelCase）檢查過，轉成資料表的欄位；不合格的丟 `Invalid`，原因會回給網頁。`validate_look()` 檢查一套造型，只留認得的欄位；`owner_of()` 把瀏覽器的金鑰換成雜湊。
- `Store`：SQLite 的包裝。`add()` 存一批、`count()` 回筆數、`boards()` 算三個個人榜（附榜上角色的造型）、`training()` 算練功榜、`set_look()` 設或拿掉一個角色的造型、`my_looks()` 列一把金鑰名下的角色。算好的結果快取 60 秒，有寫入或改了造型就清掉。沒有刪除：收下的紀錄要拿掉只能直接改資料檔。
- `RateLimiter`：每個 IP 每分鐘的請求數（固定視窗），只放在記憶體，重開就歸零。
- `client_ip()`：決定上傳者的 IP。連線來自本機（也就是通道）時才信 `CF-Connecting-IP` 或 `X-Forwarded-For`，直接連進來的人自己填的標頭不算數。
- `Handler`：路由與回應，跑在 `ThreadingHTTPServer` 上，每個連線一條執行緒，15 秒沒動靜就斷。正常的請求不寫 log，只留 400 以上的（journal 也在 SD 卡上）。

### API

| 方法與路徑 | 內容 | 回應 |
| --- | --- | --- |
| `POST /api/records` | `{"key", "records": [...]}`，1 到 100 筆；`key` 是瀏覽器的金鑰，可以不帶（舊版網頁） | `200`，`{"accepted": [uid], "rejected": [{"uid", "reason"}]}`；已經有的 uid 也算 accepted |
| `POST /api/looks` | `{"key", "character", "look"}`；`look` 給 `null` 是拿掉 | `200`，`{"ok": true}`；這把金鑰沒傳過那個角色的紀錄回 `403` |
| `POST /api/looks/mine` | `{"key"}` | `{"characters": [{"character", "look"}]}`：這把金鑰名下的角色與各自目前的造型（沒設是 `null`） |
| `GET /api/leaderboard` | `?days=7&limit=50`；`days` 不給就是全部，`limit` 最多 200 | `{"days", "exp": [...], "rate": [...], "level": [...], "looks": {角色: 造型}}` |
| `GET /api/training` | `?days=7&job=法師&level=35&limit=100`；都可以不給，`level` 給區間裡任何一級都行 | `{"days", "jobs": [...], "levels": [...], "rows": [...]}` |
| `GET /api/health` | | `{"ok": true, "records": 筆數}` |
| `GET /` | | `302` 轉去網站的排行榜頁籤 |
| `POST /api/records/delete`、`DELETE /api/records/<uid>` | v0.33 以前的網頁刪紀錄時會叫 | `204`，但什麼都不刪；留著是因為舊網頁收到錯誤會一直重試、後面的紀錄也傳不上來 |

個人榜（`/api/leaderboard`）三個都是每個角色一列：`exp` 是總經驗（那個角色所有紀錄的經驗加起來，附最高等級、活躍時間、筆數），`rate` 是最高效率（EXP / hr 最高的那一筆，附那一筆的等級與地圖），`level` 是最高等級。職業取該角色最近一筆有讀到職業的。`looks` 是這次回應裡出現的角色中有設造型的（網頁的頒獎台畫全身、名單畫頭像）。

練功榜（`/api/training`）是每個「地圖 × 職業 × 等級區間」一列：把同一組的紀錄合起來，總經驗 ÷ 總活躍時間，效率高的在前，附累計活躍時間、紀錄數、角色數。等級每 10 級一個區間（1–10、11–20…）；地圖用名字分，沒讀到地圖、職業或等級的紀錄不算。`jobs` 與 `levels` 是這段期間有資料的職業與區間起點，給網頁做篩選的下拉選單。這個榜不帶任何角色名字。

uid、IP 與金鑰（連雜湊）不會出現在任何回應裡。

### 資料表

`records` 一筆紀錄一列：

| 欄位 | 內容 |
| --- | --- |
| `uid` | 主鍵。網頁從紀錄內容算出來的指紋，排成 UUID 的樣子 |
| `character`、`job`、`level` | 角色、職業（可以是空的）、等級（可以沒有） |
| `map_id`、`map_name` | 地圖的像素指紋與名字 |
| `start_at`、`end_at` | 起訖時間（毫秒） |
| `cum_net`、`active_sec`、`idle_sec` | 累計經驗、活躍秒數、閒置秒數 |
| `ip`、`received_at` | 上傳者的 IP、後端第一次收到的時間（毫秒） |
| `owner` | 傳這筆紀錄的瀏覽器：金鑰的 SHA-256。這一欄加上去以前收的紀錄是空的，等那個瀏覽器下次開頁重傳時補上 |

索引有 `(character, end_at)`、`(end_at)` 與 `(owner, character)`。舊的資料檔在服務啟動時會自動補上 `owner` 欄。

`looks` 一個角色一列，有設造型的才有：

| 欄位 | 內容 |
| --- | --- |
| `character` | 主鍵，角色名字 |
| `look` | 造型，一段 JSON：`skin`、`hair`、`face`、`mix`（髮色與瞳色的混色）、`worn`（部位 → 時裝編號）、`group`（武器類型） |
| `owner`、`ip`、`updated_at` | 最後一次是哪把金鑰、從哪個 IP、什麼時候設的 |

### 重複與刪除

後端只靠 `uid` 認重複，內容不比對：`INSERT ... ON CONFLICT (uid) DO NOTHING`，同一個 `uid` 再來幾次都只有一筆，IP 與收到時間留第一次的。網頁每次開啟都會把手上的紀錄整批重傳，靠的就是這個；`uid` 由網頁的 `recordUid()` 從紀錄編號、角色、起訖時間、經驗算出來，同一筆不管重傳幾次、在哪個分頁算都一樣。

收下的紀錄不刪：使用者在網頁的歷史紀錄裡刪掉一筆、全部清除，或把上傳關掉，後端的都留著。沒有對外的刪除功能，真的要拿掉某一筆（例如明顯造假的）只能在主機上直接改資料檔。

### 金鑰與造型

沒有登入，但「誰能改這個角色的造型」需要一個依據：每個瀏覽器第一次上傳時自己產生一把金鑰（一串亂數，存在 localStorage 的 `mapleexp.syncKey`），之後每次上傳都帶著，後端把它的雜湊記在收下的每筆紀錄上（`owner`）。先傳的人是主：已經有主的紀錄，別人再重傳同一筆不會改。這個功能上線前收的紀錄沒有主，網頁每次開頁都會整批重傳，所以原本的使用者下次開頁就自動認領完。

一把金鑰只要名下有那個角色的任何一筆紀錄，就能設或拿掉那個角色的造型；同一個角色在兩台電腦都有紀錄，兩邊都能改，後設的蓋掉先設的。清掉網站資料金鑰就沒了，新的金鑰要等傳上去一筆那個角色的新紀錄才有資格。這擋不了有心人（偽造一筆同名的紀錄就有資格），跟排行榜的數字本身一樣只防君子；`looks` 記著最後是哪把金鑰、哪個 IP 設的，出事時查得到。

造型只是零件編號，後端只檢查格式（整數、範圍、部位名稱是英文字母、最多 24 個部位），不管那個編號存不存在：畫的是網頁，遇到不認得的編號（例如下一版客戶端拿掉的時裝）就當作沒穿。因為不收圖片，沒辦法拿排行榜放任意的圖。

### 限制

- 每個 IP 每分鐘最多 120 個請求，超過回 `429`。
- 一個請求的內容最多 128 KB，一批最多 100 筆。
- 資料檔超過 200 MB 或磁碟剩不到 100 MB 就不再收新紀錄，回 `507`；排行榜照常。
- 活躍不滿 10 分鐘的紀錄不收（網頁連存都不存）；這個門檻加上去以前收下的短紀錄，服務啟動時會清掉。
- 每筆紀錄擋掉格式不對與明顯不可能的值：角色最多 24 字、等級 1 到 300、時間不早於 2020 年也不晚於現在加一天、活躍與閒置各不超過 30 天、經驗是正數且不超過 10 的 13 次方。
- 數字是瀏覽器自己算好傳上來的，上面這些擋不了有心造假。

### 安裝、更新與維護

第一次安裝照 `server/prisondiary-api.service` 開頭的說明做，再在主機上裝 Tailscale、登入、執行 `tailscale funnel --bg 8787`（第一次會給一條連結，要到 Tailscale 後台同意啟用 Funnel）。

程式改了要自己複製過去再重啟，服務中斷幾秒，網頁傳不上去的會自己再試：

```bash
scp server/app.py <使用者>@<主機>:prisondiary-api/app.py
ssh <使用者>@<主機> systemctl --user restart prisondiary-api
```

網頁與後端都要改的時候先更新後端：舊網頁還會被瀏覽器快取一陣子，後端要同時認得新舊兩種請求。

| 要做的事 | 指令（在主機上） |
| --- | --- |
| 看服務狀態 | `systemctl --user status prisondiary-api` |
| 看 log | `journalctl --user -u prisondiary-api` |
| 看目前筆數 | `curl http://127.0.0.1:8787/api/health` |
| 看通道 | `tailscale funnel status` |
| 備份資料檔 | 複製 `records.db`，服務跑著的時候要連同 `-wal` 檔一起，或用 `python3 -c "import sqlite3; sqlite3.connect('records.db').backup(sqlite3.connect('備份檔'))"`（主機上沒有 `sqlite3` 指令） |

本機開發時不用改程式：`python server/app.py` 起一個只聽本機的後端（資料檔預設在 `server/data/records.db`），再開 `http://localhost:8765/?api=http://127.0.0.1:8787`，網頁就會指到它（記在瀏覽器裡，`?api=` 取消；只有本機開的頁面能這樣改）。

測試都不需要遊戲或瀏覽器：視覺管線用 `src/mapleexp/testfont.py` 的點陣字型合成畫面，

```powershell
python -m venv .venv

```
